Camera cleanliness monitoring

2025 — present · computer vision, integration · professional

A large surveillance deployment had no way to know which of its cameras had degraded. Dust, rain, blur, obstruction — finding out meant a person opening feeds one at a time.

I built the system that answers it automatically. Frames are pulled from the VMS, classified on-server, and surfaced as operational state rather than raw model output.

The constraint that shaped it

The inference server has no internet access and modest CPU. I trained a lightweight classifier and exported it to ONNX rather than shipping a Python runtime — the .NET scanner loads a single file and has no dependency chain to vendor onto an offline machine.

What the numbers actually say

Validation accuracy landed between 0.76 and 0.88 across runs. That spread is the honest figure, and it is the reason uncertain predictions route to manual review instead of being auto-actioned.

Frames were grouped by source video before splitting. Near-duplicate frames either side of a split will invent accuracy that isn't there.

How the pieces fit

Milestone XProtect supplies camera access. A .NET scanner retrieves one representative JPEG per camera per scan, on a schedule or on demand. The ONNX classifier scores it, and the scanner records the prediction, confidence, and frame path. A REST API exposes those results to a Laravel dashboard that handles status, history, filters, charts, and the manual-review queue — with SQLite for early development and MySQL for broader deployment.

Building the Laravel side of that dashboard was the reason I took a full-stack PHP and Laravel course partway through — learning aimed at a specific piece of live work rather than studied in isolation.

Built with

PyTorch · ONNX Runtime · ASP.NET Core 8 · Laravel · MySQL · Windows Server
